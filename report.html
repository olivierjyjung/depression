SER은 도움이 되었나

담당 정지윤 기간 9/9 – 9/15 데이터 DAIC-WoZ 189명 (train 107 / dev 35 / test 47)

사수 가설(SER 사전학습 > ASR 사전학습)은 성립했습니다. 그러나 그 위에서 성능을 더 올렸는지는 DAIC-WoZ 189명으로는 측정이 불가능하며, 그 한계를 숫자로 확정했습니다 — 지금 보이는 크기의 개선을 증명하려면 화자 210명(간신히) ~ 860명(여유)이 필요합니다.

§1 사수 질문에 대한 직접 답

9/9에 결과 보기 전에 1차 게이트를 “test AUC가 0.626을 넘는가”로 지정했고, emotion2vec+는 통과했습니다.

whisper-SER은 통과로 읽지 않았습니다 — dev 0.449(찍기 이하)인데 test만 0.636으로, 두 평가셋이 정반대면 신호가 아니라 잡음입니다. 학습 데이터가 RAVDESS/SAVEE/TESS/URDU 합계 약 4,170개의 연기(acted) 클립이라 자연 인터뷰와 도메인 갭이 큰 것도 이유입니다.

emotion2vec+가 수치상 약 0.09 앞섭니다. 단 짝지은 신뢰구간이 0을 포함해 (−0.092 [−0.203, +0.019]) 확정은 못 합니다 — §4의 측정 한계가 모델 비교에도 걸립니다.

Emotion2Vec-S 해석 주의. S의 utterance 출력은 토큰 10개 × 768이고 C²SER 원설계는 그 10개를 오디오-LLM에 입력합니다. 저희는 로지스틱에 넣기 위해 10개를 평균했습니다(결과 보기 전 확정한 선택). 따라서 결론은 “문서화된 utterance 출력을 평균해서 쓰면 emotion2vec+보다 못하다”이며 “S가 열등한 모델”은 아닙니다. S는 독립 embedding 추출기가 아니라 LLM용 인코더로 설계되었습니다.
라이선스. Emotion2Vec-S는 Apache 2.0으로 사용 가능합니다. 반면 도메인이 가장 가까웠던 whisper-large-v3-msp-podcast-emotion(MSP-Podcast 자연발화, INTERSPEECH 2025 상위 파이프라인)은 Open RAIL로 “clinical or diagnostic applications”를 명시적으로 금지해 후보에서 제외했습니다.

§2 실행한 파이프라인

추출 소요 emotion2vec+ 4.7분 · Emotion2Vec-S 2.7분 (GPU 1장) · 실패 0건

  1. 오디오 확보 — DAIC wav 189개(5.4GB)를 allen ojjung_ser 컨테이너로 전송 (권한 700)
  2. 참가자 구간만 분리 — 전사의 Participant 줄만 사용. Ellie 목소리는 189명 전원에게 동일하므로 넣으면 화자 간 차이가 희석됩니다
  3. 턴 단위로 묶음 (사수 9/11 확정) — 연속 Participant 줄 = 1턴. 줄 단위는 중앙값 1.96초·67%가 3초 미만으로 SER 모델 입력에 부적합하고, 턴으로 묶으면 중앙값 5.16초가 됩니다. 총 10,792턴
  4. 30초 초과 턴 분할, 50ms 미만 조각 제외, 짧은 턴은 버리지 않고 길이 가중평균 — 짧게 답하는 것 자체가 우울 신호일 수 있어 컷을 두지 않았습니다
  5. 분류 층 직전 표현 추출 (사수 지시대로) — emotion2vec+ 1024차원 + 9-class 감정 확률, Emotion2Vec-S 768차원
  6. 평가 — L2 로지스틱. 정규화 강도·PCA 성분 수를 train 안에서만 교차검증으로 선택, threshold도 train에서 고정, dev/test는 1회 통과

§3 2단계(융합 기여) 판정 — 측정 불가

9/9에 채택 기준을 “기존 최고 시스템에 얹었을 때 올라가는가”로 사전 지정했습니다. 0821의 화자별 text 점수 파일이 남아 있지 않아, 전사만으로 재계산 가능한 응답 지연을 기준선으로 대체했습니다 (재현 검증: test 0.773 vs 0821의 0.776).

  • emotion2vec+를 응답 지연에 얹은 결과: dev +0.123 / test −0.039 — 두 평가셋이 정반대
  • paired bootstrap 1만 회 결과 dev·test × 4조합 8개 비교 전부 신뢰구간이 0을 포함

즉 “기여 없음”이 아니라 “기여를 확인할 수 없음”입니다. 이 구분이 이번 보고의 핵심입니다.

§4 가장 중요한 발견 — 평가셋의 검정력 한계

test 47명(양성 14명)에서 ΔAUC 신뢰구간 반폭이 ±0.13 ~ ±0.19

구별 가능 최소 차이

0.03–0.07AUC · 양성 14 × 음성 33 = 462쌍
필요 화자 수
210 – 860+0.081 증명용 · 간신히 / 여유

직관적으로: AUC는 양성 14명 × 음성 33명 = 462쌍의 순서를 재는 값이라, 한 사람의 순위가 바뀌면 AUC가 0.03~0.07 움직입니다. “+0.03 개선”은 곧 “한 명이 자리를 바꿨다”는 뜻입니다.

함의 3가지

  1. SER뿐 아니라 어떤 speech feature를 얹어도 이 평가셋으로는 기여 판정이 원리적으로 불가합니다
  2. 0821 표의 “융합에서 latency가 test AUC를 +0.01~0.03 올린다”도 이 잡음 범위 안이므로 해당 수치들은 재해석이 필요합니다
  3. augmentation의 논거가 정밀해집니다 — “데이터가 적어서 성능이 안 나온다”가 아니라 “화자가 적어서 개선 여부를 측정할 수 없다”입니다. 후자는 화자 수를 늘리는 것 외에 해결책이 없습니다

§7 부산물 — DAIC 전사에 질문 ID가 들어 있음

SER 성과와 별개로, 이번 조사에서 팀에 가장 바로 쓰이는 산출물

DAIC 전사 189개 중 124개는 Ellie 발화를 question_id (실제 문구) 형식으로 기록하고 있습니다.

744.124  745.934  Ellie  depression_diagnosed (have you been diagnosed with depression)
796.177  799.902  Ellie  happy_lasttime (tell me about the last time you felt really happy)
  • 태그된 124세션에서 ID → 정식 문구 사전 150개를 학습해 나머지 65세션을 문구 매칭으로 복원
  • 결과: 참가자 발화의 99.7%(화자별 중앙값)가 질문 ID로 정렬됩니다. 186/189명이 50% 이상
  • 질문 ID 161종. 화자 90% 이상 5종 / 75% 이상 16종 / 50% 이상 41종. 화자당 중앙값 47종
  • 0902 문서의 “Ellie는 100여 개 고정 질문을 정해진 흐름으로 묻는다”가 데이터로 확정되었고, 실제 질문 목록·순서·커버리지가 확보되었습니다

덮이는 질문이 PHQ-8과 대응됩니다 — easy_sleep(91%) control_temper(93%) feel_lately(85%) depression_diagnosed(88%) ptsd_diagnosed(87%) regret(80%) last_argument(96%) sleep_affects(66%) behavior_changes(66%) happy_lasttime(64%).

→ augmentation의 Ellie LLM이 따라야 할 질문 흐름 사양으로 즉시 쓸 수 있습니다.

§8 한계 및 주의사항

  1. 감정 분포가 한쪽으로 쏠려 있음 — 발화 길이 가중 기준 sad 0.47 / happy 0.21 / neutral 0.20 / unknown 0.10, 나머지(angry·disgusted·fearful·surprised) 합 0.015. 즉 여기서 “부정감정”은 사실상 sad 확률 하나입니다. 조용하고 느린 인터뷰 말투를 모델이 전반적으로 sad로 읽는 도메인 편향일 수 있습니다
  2. Emotion2Vec-S의 pooling은 저희 선택 — §1 Q2 참고
  3. 전사에 Ellie 줄이 아예 없는 세션 3개 (pid 451·458·480). 응답 지연이 정의 불가하여 train 중앙값 대체 / 해당 화자 제외 두 방식을 모두 보고했고 결론은 동일했습니다. 0902 문서가 E-DAIC의 결함으로 지적한 현상이 DAIC 안에도 존재합니다
  4. 0821 lat의 dev 값을 재현하지 못했습니다 — test는 0.773 vs 0.776으로 일치하나 dev는 0.627 vs 0.678로 벗어납니다. 원인 미확인이며, 0821 코드·산출물 소재 확인이 필요합니다
  5. cv189는 보조 지표입니다 — 공식 split을 벗어나므로 0821 표나 논문 수치와 직접 비교할 수 없습니다. 공식 split 수치는 그대로 유지했습니다
  6. 저희 평가 코드에서 버그를 한 건 발견해 정정했습니다 — 폴드별 예측 확률을 척도 보정 없이 합쳐 AUC가 0.08~0.12 깎이고 있었습니다(응답 지연 0.557 → 0.634). 단일 feature의 “값 그대로 AUC”와 “out-of-fold AUC”가 달라 발견했습니다. 이 버그로 한 번 잘못된 결론(+0.142, “처음으로 잡음을 넘었다”)을 냈다가 뒤집었으며, 본 보고서 수치는 모두 수정 후 값입니다
  7. Emotion2Vec-S 환경 제약 — fairseq 0.12.2 + hydra 1.0.7 + omegaconf 2.0.x는 Python 3.11에서 동작하지 않습니다. 별도 conda env(Python 3.10) + timm 0.6.x 고정 + torchvision 재설치가 필요합니다. 상세는 DECISIONS.md 2026-09-15 항목에 기록했습니다

§9 판단 요청 사항

  1. speech 가지를 화자 수 확보 전까지 보류할지. 현 상태로는 무엇을 만들어도 개선 증명이 불가하며, 이는 feature 설계 문제가 아니라 평가셋 크기 문제입니다
  2. augmentation을 “측정 가능성 확보” 목표로 재정의할지. 목표 화자 수를 210~860명으로 두면 근거가 명확해집니다 (PsyGAT 992세션이 이 구간)
  3. Emotion2Vec-S를 원설계대로 재시도할지 — 10개 토큰을 평균하지 않고 오디오-LLM 인코더로 사용하는 경로. 저희 평균 방식의 결과만으로 S를 기각하기에는 근거가 약합니다
  4. 시간 구조(timing) 계열에 집중할지. 세 번의 시험에서 살아남은 것은 전부 시간 관련 feature였습니다. 0901 문서의 short-context timing feature 설계서를 이 방향으로 살릴 수 있습니다
